# Безопасность

## Модель угроз

Сервис работает на рынке РФ. Основные риски:
- блокировка протокола/серверов (DPI);
- компрометация серверов и утечка ключей/UUID;
- недоступность панели/сайта;
- потеря БД (платежи, подписки).

## Что сделано

### SSH (все машины)
- `PasswordAuthentication no`, `KbdInteractiveAuthentication no`
- `PermitRootLogin prohibit-password` (root только по ключу)
- `MaxAuthTries 4`, `X11Forwarding no`
- fail2ban: джейл `sshd` (aggressive), баны через nftables, инкремент бантайма до 1 недели
- root-пароли ротированы, хранятся вне репозитория (менеджер секретов / `~/.vpn-secrets`)

### nftables (default-drop)
- Ноды: открыты только `22`, `443`; `8090` — только с IP панели.
- Панель: открыты `22`, `80`, `443`, `21115-21119`; закрыты `2096` (legacy), `22825` (3x-ui),
  `3000` (сайт напрямую), `8090`.
- Правила идемпотентны (отдельная таблица `vpnfilter`), не сносят таблицу fail2ban,
  переживают ребут.

### Панель приложения
- 3x-ui доступен только с localhost (через SSH-туннель).
- Сайт наружу — только через Caddy (TLS).
- fail2ban `3x-ipl` защищает логин 3x-ui.

### Reality-маскировка
- Обычный TLS-клиент с SNI `vpnsh.ru` видит валидный сертификат и сайт.
- `dest` панели — `127.0.0.1:8443` (Caddy), нод — реальный внешний сайт.

### Бэкапы
- Ежедневно 03:30 UTC: `x-ui.db` (онлайн) + снапшот PGlite + конфиги.
- Отгрузка off-site на ноду DE, ротация 14 дней, sha256-манифест.

## Что делать регулярно
- Обновлять Xray / x-ui / Caddy / ОС (unattended-upgrades включён).
- Ротировать UUID/shortId при подозрении на утечку (см. `docs/runbook.md`).
- Проверять, что `:2096` не нужен (подписки идут через `/sub`).
- Следить за сроками сертификатов (Caddy обновляет сам).

## Секреты (не в репозитории)
- `/etc/vpn-web.env` — платёжные и Telegram-ключи, LEGAL_*.
- Xray `privateKey`, UUID, `shortId` — в конфигах и БД, не в git.
- SSH-ключи, root-пароли — вне репозитория.
